This is intentional protection. The bot was actively scanning every 60s — logs showed it checking —
but correctly blocking new Post-Open trades until the volatile day rolls out of the 3-day window.

## Bugs Fixed This Session

### ORDER REJECTED: Brackets cannot be used with Position Brackets
TopstepX "Position Brackets" setting conflicts with API bracket orders.
**Fix:** Removed `stop_loss_ticks` and `take_profit_ticks` from all `place_order()` calls.
Position monitor in `auto_trader.py` now handles SL/TP manually every 30s:
```python
# Hard SL check
sl_price = _active_trade.get("stop_price")
hit_sl = (side == 0 and cur_price <= sl_price) or (side == 1 and cur_price >= sl_price)
if hit_sl: await px.close_position(sym)

# Take profit check
tp_price = _active_trade.get("tp_price")
hit_tp = (side == 0 and cur_price >= tp_price) or (side == 1 and cur_price <= tp_price)
if hit_tp: await px.close_position(sym)
```

## Notes on Vol Regime Filter
The bot uses a 3-day rolling window to check if any recent day had > 3.5% intraday range.
On high-volatility days (like June 9, 2026 with 5.7% MNQ range), Post-Open trades are blocked.
This is intentional protection — it clears automatically as the volatile day ages out.
