# Session 2026-06-10 — Progressive Profit Protection + Bracket Fix

## Changes Shipped (commit 139b9b5)

### 1. Bracket Order Fix (`backend/providers/projectx.py`)
ProjectX API uses `ticks` not `tickDistance` in the `PlaceOrderBracket` schema.
Previous code was sending `{"tickDistance": N, "type": 4}` which the API silently treated as `ticks: 0`, causing:
> ORDER REJECTED: Invalid stop loss ticks (0). Price should be at least 4 ticks away.

Fixed to:
```python
payload["stopLossBracket"] = {"ticks": stop_loss_ticks, "type": 4}   # 4 = Stop
payload["takeProfitBracket"] = {"ticks": take_profit_ticks, "type": 1} # 1 = Limit
```

Both the ICT swing and 3-bar reversal `place_order()` calls now pass `stop_loss_ticks` / `take_profit_ticks`.

### 2. Progressive Profit Protection (`backend/engines/auto_trader.py`)

Replaces the old single `DAILY_TARGET = 600` with a tiered floor system:

| P&L Hits | Floor Locks At | Size Factor |
|----------|----------------|-------------|
| $500     | $500           | 100%        |
| $600     | $600           | 80%         |
| $750     | $750           | 70%         |
| $1000    | $1000          | 50%         |
| $1500    | $1500          | 0% (done)   |

- **Max daily loss:** $1000 (hard lock — account stops trading)
- **Max daily profit:** $1500 (done for the day)
- Floor logic: once P&L retreats to the locked floor, trading stops for the day
- Size scales down automatically as floors lock in

### 3. P&L Display Fix (`backend/engines/auto_trader.py`)
`_sync_pnl()` was using a 24-hour rolling UTC window, picking up trades from previous sessions.
Fixed to use 6 PM ET as the futures session start time. If it's before 6 PM ET, session started
at 6 PM yesterday.

### 4. Bot UI Update (`frontend/src/pages/Bot.jsx`)
Status bar now shows:
- **Profit Floor** — current locked floor (yellow if active, gray if none)
- **Size Factor** — current contract scaling (yellow if reduced)
- **Max Profit** — $1500
- **Max Loss** — $1000
